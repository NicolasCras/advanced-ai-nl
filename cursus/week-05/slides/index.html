10:45 · Evals

Zo testen bedrijven AI

Veel gevallen, automatisch nagekeken, bij elke wijziging opnieuw.

Veel gevallenMeer vragen met automatische beoordeling verslaan weinig vragen met handwerk. Anthropic
Drie beoordelaarscode (snel, zonder nuance) · mens (traag, duur) · een LLM: eerst testen, dan opschalen. Anthropic
LLM nagekeken door mensenHoneycomb: 3 rondes tot de LLM-beoordelaar het in meer dan 90% eens was met een expert.
Bij elke wijziging opnieuwContinue evaluatie, de testset groeit mee. OpenAI · Rechat: honderden tests bij elke wijziging.
Meerdere runs per gevalτ-bench: GPT-4o loste ± 61% op in één run, maar minder dan 25% in alle 8 runs.
Eigen evals, geen ranglijstEen publieke benchmark test jouw toepassing niet. Haal nieuwe gevallen uit je logs. OpenAI

11:00 · Lus 1 · Plak dit bij je agent

Plak dit bij je agent

Draai mijn foutmargetest. Neem mijn laatste versie van de prompt en de versie ervoor, uit `build/`, of uit git als ze daar niet meer staat. Draai beide op dezelfde inputs uit `build/test-set.md`, 3 runs per versie, op hetzelfde model als mijn testset. Elke run in een nieuwe, aparte sessie met alleen de prompt en de input, zonder tools: bij Claude `claude -p --tools ""`, bij Codex `codex exec`. Draai ze parallel als dat kan. Geef het model nooit de verwachte antwoorden. Vergelijk daarna elk antwoord met het verwachte antwoord uit mijn testset, en maak een tabel: de score per run per versie, en per versie de laagste en de hoogste score. Noteer het model. Pas mijn verwachte antwoorden niet aan. Zet alles in `build/foutmarge.md`.
